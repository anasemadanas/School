# Logical Model

The logical model lists every entity with its attributes, identifiers and relationships, using DBMS-independent **domains**.

| Diagram | Content |
|---|---|
| [diagrams/logical/master_logical.puml](../diagrams/logical/master_logical.puml) | All entities with their primary identifiers, and every relationship |
| [diagrams/logical/modules/*.puml](../diagrams/logical/modules) | Full attribute lists, PK/FK/alternate-key markers, allowed values, and the module's business rules as a note |

The full attribute list of every entity, with its physical type, is in [TABLE_CATALOG.md](TABLE_CATALOG.md).

## Domains

| Domain | Meaning | Physical mapping (see PHYSICAL_MODEL.md) |
|---|---|---|
| Identifier | Surrogate key or reference to one | INT, or BIGINT for high-volume entities |
| Text(n) | Unicode text, max *n* characters | NVARCHAR(n) |
| LongText (JSON) | Unbounded JSON document (audit images only) | NVARCHAR(MAX) + ISJSON check |
| Integer | Whole number | TINYINT / SMALLINT / INT |
| Decimal | Score or grade point | DECIMAL(9,3) / DECIMAL(3,2) |
| Money | Monetary amount | DECIMAL(19,4) everywhere |
| Percentage | 0–100 with 4 decimals | DECIMAL(7,4) |
| Date / Time / Timestamp | Calendar date / time of day / UTC instant | DATE / TIME(0) / DATETIME2(3 or 7) |
| Flag | Yes/no | BIT |
| Binary | Opaque bytes (password hash) | VARBINARY(256) |

Notation in the diagrams: `*` mandatory, «PK» primary key, «FK» foreign key, «AKn» alternate key *n*, `{a | b}` allowed values (from CHECK constraints). Every business entity also carries the audit attributes (created/updated at and by), shown as a single line labelled «audited». Physical-only columns are summarised instead of listed: the row version used for optimistic concurrency, and the system-time period columns of temporal tables.

## Identifiers and alternate keys

Every entity has a surrogate identifier. Natural business keys are enforced as alternate keys, for example:

- Student number, employee number, application number, invoice number and receipt number.
- One enrollment per (student, academic year).
- One section code per (year, branch, grade).
- One curriculum subject per (year, grade, program, subject).
- One result per (assessment, enrollment).
- One attendance record per (session, enrollment).

Pure associative entities (RolePermissions) use their composite key as the identifier.

## Normalisation

All entities are in **3NF**. Every non-key attribute depends on the key, the whole key, and nothing but the key. Lookup lists (fee types, statuses, relationship types…) are separate entities, so their descriptions aren't repeated.

### Deliberate denormalisation

Each case is listed with the rule that keeps the copied values consistent.

| Where | What is repeated | Why | Consistency guaranteed by |
|---|---|---|---|
| attendance.AttendanceRecords | SessionDate, SectionId (copied from the session) | Supports the two hot access paths: attendance by student + date and by section + date, without joining the session table on tens of millions of rows | Composite FK (AttendanceSessionId, SessionDate, SectionId) → UNIQUE key on AttendanceSessions |
| enrollment.SectionAssignments | AcademicYearId | Guarantees the section and the enrollment belong to the same year | Composite FKs (EnrollmentId, AcademicYearId) and (SectionId, AcademicYearId) |
| finance.Invoices | Subtotal, discount, tax and total; PaidAmount; CreditedAmount | Statements and receivables without aggregating lines and allocations | Set only by procedures; CHECK Total = Subtotal − Discount + Tax; validation checks totals = Σ lines, Paid = Σ allocations, Credited = Σ credit notes |
| assessment.ReportCards / ReportCardLines | Computed percentages, letters and attendance counts | A published report card is a legal snapshot and must not change when results are corrected later | Generated by `usp_GenerateReportCards`. Re-issuing creates a new version and the old one becomes Superseded. |

## Business constraints (summary)

The full rule list, with where each rule is enforced, is in [BUSINESS_RULES.md](BUSINESS_RULES.md). The most important rules at the logical level are:

1. A person can hold several roles at once (overlapping specialisation). Teacher is a specialisation of Employee.
2. The academic year scopes enrollments, sections, the curriculum, timetables (through terms), assessments (through terms) and fee structures. Closed years are never edited.
3. A student has at most one enrollment per year and at most one open section placement.
4. A payer is exactly one guardian or one sponsor. The payer shares of an enrollment total 100%.
5. Issued invoices are immutable. Corrections go through credit notes, and an unpaid invoice can be cancelled.
6. Assessment weights per subject and term total 100. A score lies between 0 and MaxScore.
7. **There is no limit on the number of students** anywhere in the model.

## Mapping logical → physical

| Logical | Physical |
|---|---|
| Entity | Table `schema.PluralName` |
| Identifier | `<Entity>Id` INT/BIGINT IDENTITY(1,1), PK_<schema>_<Table> |
| Subtype identifier | Same column as the supertype key: PK and FK at the same time |
| Alternate key | UNIQUE constraint `UQ_…`, or a filtered UNIQUE index `IX_…` when it applies to a subset of rows |
| Allowed values | CHECK constraint `CK_…` |
| Relationship | FOREIGN KEY `FK_<Child>_<Parent>[_<Column>]` plus a supporting index |
| «audited» | CreatedAt, CreatedBy, UpdatedAt, UpdatedBy with DF_ defaults |
| «history kept» | System-versioned temporal table, with history in the `audit` schema |
